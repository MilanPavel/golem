Found it. The client decodes each socket chunk on its own, in connect.ts line 619. The socket hands over bytes in pieces of whatever size the kernel had ready, so on a long answer a piece can end in the middle of a character. Each half is then decoded alone, and both halves become �.

The fix is a decoder that keeps an unfinished character until the next chunk arrives:

const decoder = new TextDecoder("utf-8");
// stream: true holds back a split character for the next call
buffer += decoder.decode(chunk, { stream: true });
